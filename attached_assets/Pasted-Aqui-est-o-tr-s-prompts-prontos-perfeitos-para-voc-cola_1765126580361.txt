Aqui estão **três prompts prontos**, perfeitos para você colar no Replit Agent ou usar em qualquer assistente que manipule código — cada um focado em uma das etapas que você pediu.

Eles estão escritos de forma **cirúrgica**, para evitar que a IA quebre o projeto, altere layout ou delete arquivos indevidamente.

---

# ✅ **PROMPT 1 — ORGANIZAR O PROJETO PÓS-IMPORTAÇÃO (Lovable → GitHub → Replit)**

> Quero que você organize o projeto pós-importação sem mudar o layout, o visual ou a arquitetura original do Lovable.
> Siga estes passos **exatamente**, sem adicionar frameworks, sem refatorações e sem substituir componentes:
>
> **1. Estruturação**
>
> * Revise a árvore de pastas e confirme se os diretórios estão organizados como `src/`, `components/`, `pages/` ou `app/`, conforme o framework do projeto.
> * Ajuste somente nomes inconsistentes ou duplicados de arquivos.
> * Remova arquivos temporários como `.DS_Store`, `Thumbs.db`, pastas duplicadas e arquivos `.old`.
>
> **2. Dependências**
>
> * Revise o `package.json`, mantendo apenas dependências realmente utilizadas pelo código.
> * Remova dependências não utilizadas (com segurança).
>
> **3. Scripts**
>
> * Verifique scripts de execução: `"dev"`, `"build"`, `"start"`.
> * Garanta que funcionam corretamente no Replit.
>
> **4. Resumo final**
> Após organizar tudo, gere um relatório contendo:
>
> * Arquivos removidos
> * Arquivos reorganizados
> * Dependências removidas ou ajustadas
> * Novo mapa da estrutura do projeto.
>
> ⚠️ **Atenção:** não alterar componentes, CSS, design, layout, textos ou lógica funcional. Somente organização estrutural.

---

# ✅ **PROMPT 2 — LIMPAR CÓDIGO LOVABLE (APENAS O NECESSÁRIO)**

> Quero que você faça uma limpeza suave do código gerado pelo Lovable, **sem alterar o funcionamento do site, estilos, animações ou estrutura visual**.
> Remova apenas o que for lixo gerado automaticamente.
>
> Siga os passos:
>
> **1. Identificar resíduos do Lovable**
>
> * Remova comentários automáticos extensos do tipo `// Generated by Lovable`.
> * Remova imports não utilizados.
> * Remova hooks criados e não utilizados.
> * Exclua variáveis dead code.
>
> **2. Componentes e CSS**
>
> * Não modifique estilos, não renomeie classes, não reestruture JSX.
> * Apenas remova trechos realmente inúteis.
>
> **3. Melhorias leves (sem refatorar)**
>
> * Organize imports.
> * Padronize espaçamento e formatação (Prettier-like).
> * Padronize arquivos como `.tsx` / `.jsx` conforme necessário.
>
> **4. Relatório final**
>
> * Liste o que foi limpo.
> * Confirme que nada visual ou funcional foi alterado.
>
> ⚠️ NÃO fazer:
>
> * Não transformar arquitetura.
> * Não reescrever componentes.
> * Não mexer em lógica de UI.
> * Não trocar libs nem dependências essenciais.

# ✅ **PROMPT 3 — CONFIGURAR DEPLOY AUTOMÁTICO (GitHub Pages | Vercel | Replit Deploy)**

> Quero configurar deploy automático para o meu projeto.
> O assistente deve me oferecer opções de deploy e criar a configuração necessária para cada uma delas, mas **sem alterar o código-fonte**.
>
> Siga esta ordem:
>
> ---
>
> ## **1. Detectar o framework automaticamente**
>
> Verifique se o projeto usa:
>
> * Next.js
> * React + Vite
> * CRA
> * Node com SSR
> * Ou outro framework
>
> Gere uma resposta confirmando qual framework foi detectado.
>
> ---
>
> ## **2. Criar arquivo de configuração de deploy**
>
> Com base no framework:
>
> **Para Vercel:**
>
> * Criar `vercel.json` se necessário
> * Configurar `"output": "standalone"` para Next 13+
> * Configurar rotas caso existam caminhos dinâmicos
>
> **Para GitHub Pages:**
>
> * Criar workflow YAML em `.github/workflows/deploy.yml`
> * Ajustar `homepage` no `package.json` se necessário
> * Gerar build para diretório `dist` ou `.next`
>
> **Para Replit Deploy:**
>
> * Criar `.replit` com os comandos corretos
> * Configurar `run = "npm run dev"` ou `npm run start`
> * Verificar variáveis de ambiente necessárias
>
> ---
>
> ## **3. Criar CI/CD**
>
> Gere automaticamente o workflow GitHub Actions adequado:
>
> * Instalação
> * Build
> * Deploy automático
>
> Não modifique códigos, somente crie arquivos de config.
>
> ---
>
> ## **4. Relatório final**
>
> Depois de criar tudo, retornar:
>
> * Onde o deploy foi configurado
> * Como rodar deploy manual
> * Como funciona o deploy automático
> * Qual URL final será usada (placeholder se necessário)
>
> ⚠️ **Importante:**
> Não modificar arquivos de operação do site, apenas adicionar arquivos de configuração.
